# D06 — Procurement & Supply Chain (المشتريات وسلسلة الإمداد)
**Template:** MISHEL_MODULE_DEEP_DIVE_TEMPLATE v1.0 | **Version:** v1.0.0 | **Depth:** D5 (هدف) | **الحالة:** `SPEC DRAFT — لم يُقارَن بالكود بعد` (كل حالة UNKNOWN حتى R0/Forensic)
**ملاحظات:** هذا الموديول «محرك الالتزام والتوريد»: كل جنيه يُصرف على مواد وخدمات يمر عبر طلب شراء ثم التزام ثم استلام ثم فاتورة. يستقبل الحزم والميزانية من D03، ويغذي المخازن (D14) والمحاسبة (D13) والتكلفة (D05). كل حد اعتماد أو نسبة تسامح أو مدة في هذا الملف **مثال توضيحي قابل للضبط بواسطة Owner**؛ أي ادعاء قانوني أو جمركي أو ضريبي `PENDING EVIDENCE`.

## 1) الهوية
- **الاسم:** Procurement & Supply Chain · **العائلة:** Commitment & Supply · **Tier:** T1 (Golden Flow: BOQ ← شراء ← استلام ← فاتورة ← دفع) · **المالك:** Procurement Director + Platform Architect
- **يعتمد على:** D01 (موردون/DOA/مرجعيات)، D03 (حزم الشراء وأكواد التكلفة)، D05 (جدول الاحتياج)، D15 (ملفات)، D17 (ضمانات وتأمين).
- **يغذي:** D14 (استلام وتخزين)، D13 (Accruals، AP، التزامات)، D07 (توريد للباطن)، D11 (قطع غيار وتأجير)، D18 (تحليلات).
- **IDs:** `REQ-PRC-*`, `WP-PRC-*`.

## 2) الغرض والمستخدمون
**المشكلة:** الطلبات تأتي بالواتساب والورق، يتكرر الشراء من مورد بأسعار مختلفة، تُقسَّم الأوامر لتفادي حد الاعتماد، تُصرف فاتورة بلا استلام فعلي، ولا أحد يرى الالتزام الحقيقي مقابل الميزانية قبل فوات الأوان. المطلوب سلسلة موثقة من الاحتياج حتى الدفع مع منع التحايل وقياس أداء الموردين.
| Persona | أهم المهام |
|---|---|
| مهندس موقع / مسؤول مخزن | إنشاء PR، متابعة التوريد، تسجيل الاستلام |
| مسؤول مشتريات (Buyer) | RFQ، مقارنة عروض، إصدار PO |
| مدير مشتريات | اعتماد، تفاوض، اتفاقيات إطارية |
| مدير مشروع | اعتماد PR وفق الميزانية، متابعة التأخير |
| محاسب موردين | مطابقة ثلاثية، تسجيل الفواتير |
| مراقب تكاليف | الالتزام مقابل الميزانية |
| مسؤول جودة | تقييم المورد، قبول المواد (D09) |
| مسؤول استيراد/لوجستيات | شحن، تخليص، تتبع |
**مقياس النجاح (Owner):** زمن PR→PO · نسبة الشراء تحت اتفاقيات إطارية · نسبة المطابقة الثلاثية التلقائية · عدد الأوامر المقسّمة المكتشفة · الالتزام مقابل الميزانية لحظيًا · OTIF للموردين · نسبة الفواتير بلا استلام (هدف صفر).

## 3) السيناريوهات (Given/When/Then)
**S1 — من الاحتياج إلى PO:** Given بند حديد في ميزانية المشروع ومطلوب خلال 3 أسابيع · When ينشئ مهندس الموقع PR مرتبطًا بالبند وكود التكلفة · Then يتحقق النظام من الميزانية المتاحة، يوجه PR للاعتماد، ثم يحوله المشتري إلى RFQ أو PO مباشر من اتفاقية إطارية.
**S2 — RFQ ومقارنة عروض:** Given PR معتمد فوق حد المنافسة · When يُرسل RFQ لـ N موردين مؤهلين ويُدخل المشتري العروض · Then يُنتج جدول مقارنة (سعر، تسليم، دفع، ضمان، التزام بالمواصفات) مع ترجيح فني/تجاري وسبب اختيار غير الأرخص إلزاميًا.
**S3 — PO بسقف DOA:** Given PO قيمته تتجاوز صلاحية المشتري · When يُرفع للاعتماد · Then يتبع مصفوفة DOA حسب القيمة والفئة والمشروع، ولا يصدر للمورد قبل الاعتماد الكامل.
**S4 — منع تقسيم الأوامر (Split-Order Prevention):** Given ثلاثة PO لنفس المورد/الفئة/المشروع خلال نافذة زمنية قصيرة مجموعها يتجاوز حد المنافسة · When يُنشأ الثالث · Then يجمّع النظام القيمة التراكمية ويطبق الحد الأعلى ويحذر ويحيل للمراجعة، ولا يمر بصمت.
**S5 — الاستلام GRN:** Given PO مفتوح · When يستلم المخزن كمية أقل/أكثر/معيبة · Then يسجل GRN بالكمية المقبولة والمرفوضة وسبب الرفض، ويحدّث PO (استلام جزئي)، ويرسل حدث لـ D14 وطلب فحص لـ D09 عند اللزوم.
**S6 — المطابقة الثلاثية:** Given فاتورة مورد · When تُدخل · Then تُطابق PO/GRN/Invoice (كمية، سعر، ضريبة، شروط) ضمن تسامح قابل للضبط؛ الاستثناء يُحجز للمراجعة ولا يُدفع.
**S7 — اتفاقية إطارية (Framework):** Given اتفاقية أسعار سنوية مع مورد أسمنت · When يصدر Call-off · Then يُسحب السعر والشروط تلقائيًا ويُخصم من سقف الاتفاقية مع تنبيه عند الاقتراب.
**S8 — Expediting:** Given PO متأخر عن تاريخ الاحتياج · When يتجاوز المهلة · Then تنبيه تلقائي للمشتري والمورد، وتصعيد، وإخطار المخطط (D05) بأثر على النشاط.
**S9 — استيراد:** Given بند مستورد · When يُصدر PO بشروط تجارية دولية · Then تُتابع مراحل (طلب، تصنيع، شحن، وصول ميناء، تخليص، نقل) وتُحسب التكلفة الواصلة Landed Cost على مستوى عالٍ.
**الحالات الحدية:** PR بلا ميزانية (طلب استثناء) · مورد غير مؤهل في حالة طوارئ (شراء طارئ موثق) · تعديل PO بعد استلام جزئي · فاتورة بعملة مختلفة · استلام بلا PO (يُمنع أو Retro-PO مقيّد) · إرجاع مرتجع بعد الفاتورة · شراء لحساب الباطن (D07) · مصاريف نثرية.

## 5) دورة الحياة والـ Workflow
- **PR:** `Draft → Submitted → Approved → Sourcing → Converted → Closed / Rejected / Cancelled`.
- **RFQ:** `Draft → Issued → Closed → Evaluated → Awarded / Cancelled`.
- **PO:** `Draft → PendingApproval → Approved → Issued → PartiallyReceived → Received → Invoiced → Closed / Cancelled`; التعديل ينشئ نسخة جديدة بإعادة اعتماد.
- **Vendor:** `Candidate → Prequalified → Approved → OnWatch → Suspended → Blacklisted`.
- **Invoice:** `Received → Matching → Matched / OnHold → Approved → Posted`.
- **اعتمادات (DOA قابلة للإعداد):** حسب القيمة، الفئة، المشروع، العملة؛ استثناء الميزانية؛ الشراء الطارئ؛ اختيار غير الأرخص؛ مورد جديد؛ تغيير بيانات بنكية.
- **SLA:** مهل اعتماد وتصعيد تلقائي للمفوَّض عند الغياب.
- **التراجع:** إلغاء PO غير مستلم بإطلاق الالتزام؛ بعد الاستلام يتم عبر مرتجع وإشعار دائن.

## 6) الصلاحيات
- **SoD إلزامي:** من يطلب لا يعتمد · من يصدر PO لا يستلم · من يستلم لا يسجل الفاتورة · من يعدّل بيانات المورد البنكية لا يعتمد الدفع · لا اعتماد ذاتي ولا عبر مفوَّض يخالف السلسلة.
- نطاق: شركة/مشروع/فئة؛ مهندس الموقع يرى مشروعه فقط.
- أسعار الاتفاقيات وعروض المنافسين سرية: لا يراها طالب الشراء، ولا يرى مورد عرض غيره.
- صلاحيات حقلية: الأسعار، التقييمات، بيانات البنوك.
- تدقيق الوصول والتصدير؛ AI بصلاحية المستخدم.

## 7) الأحداث والربط التلقائي
**منتج:** `pr.approved` · `rfq.issued/closed` · `po.approved/issued/amended/cancelled` · `grn.posted` · `invoice.matched/held` · `vendor.status_changed` · `framework.threshold_reached` · `po.overdue` · `shipment.stage_changed`.
**مستهلك:** `boq.frozen` (إنشاء حزم) · `budget.updated` (D13) · `schedule.need_date_changed` (D05) · `inspection.rejected` (D09) · `stock.below_min` (D14) · `payment.executed` (D13).
**أثر:** `po.approved` ← Commitment في الميزانية (D13) · `grn.posted` ← مخزون (D14) + Accrual · `invoice.matched` ← AP · `po.overdue` ← تنبيه D05 · `vendor.blacklisted` ← منع PO جديد وتحذير على المفتوح · `inspection.rejected` ← مرتجع وخصم من تقييم المورد.
Idempotency على الاستلام والفواتير (منع الازدواج برقم فاتورة المورد + المورد + المبلغ)، وتعويض عند الفشل.

## 10) القواعد والحسابات
- **الالتزام المتاح** = الميزانية المعتمدة − الالتزامات القائمة − PR المعتمد غير المحوّل (يظهر كاحتجاز).
- **المطابقة الثلاثية:** تسامح كمية/سعر/إجمالي (أمثلة: ±X% أو مبلغ ثابت) قابل للضبط بالفئة؛ تجاوزه يحجز الفاتورة.
- **كشف التقسيم:** تجميع بالمورد+الفئة+المشروع في نافذة N يوم؛ التراكمي هو المعتمد في DOA.
- **التكلفة الواصلة** = سعر + شحن + تأمين + رسوم مرجعية + تخليص + نقل داخلي (الرسوم تُحمَّل كمرجع بإصدار — `PENDING EVIDENCE`).
- **تقييم المورد** = مجموع مرجّح (جودة، التزام مواعيد OTIF، سعر، استجابة، HSE) بأوزان من Owner؛ مؤشرات تُحسب من الأحداث لا بإدخال يدوي قدر الإمكان.
- تحويل العملات بسعر مصدره وتاريخه، وتثبيت سعر الصرف على PO حسب السياسة.
- **قاعدة ذهبية:** الأرقام من الحساب الحتمي لا من الـ AI.

## 12) التكاملات
- **Excel/PDF:** استيراد عروض الموردين وتصدير جداول المقارنة وأوامر الشراء.
- **البريد:** إرسال RFQ/PO واستقبال العروض مع ربط بالسجل.
- **ERP/محاسبة (SAP/Odoo):** مزامنة الموردين، الالتزامات، الفواتير، المدفوعات مع Mapping وتسوية.
- **بوابة الموردين:** تقديم عروض، تأكيد PO، رفع فواتير ومستندات (بصلاحيات معزولة).
- **شركات الشحن/التخليص:** تتبع مراحل عبر ملف/API حسب المتاح.
- **فاتورة إلكترونية حكومية:** حسب الدولة `PENDING EVIDENCE`.
- لكل تكامل: Mapping وإعادة محاولة وتسوية وقيود اعتمادية.

## 13) الذكاء الاصطناعي
- **PR Assistant:** يحوّل رسالة/صورة إلى PR مقترح بالبند والكمية مع الربط بـ BOQ؛ تأكيد المستخدم مطلوب.
- **Quote Parser:** يقرأ عروض PDF/Excel ويقترح جدولة بدرجة ثقة؛ مراجعة بشرية قبل اعتمادها.
- **Vendor Suggester:** يقترح موردين مؤهلين من السجل وأدائهم السابق دون اختلاق.
- **Anomaly Detector:** تقسيم أوامر، سعر شاذ مقابل التاريخ، فاتورة مكررة، مورد مرتبط بالموظف (تنبيه فقط).
- **Delay Predictor:** يتنبأ بتأخر التوريد من تاريخ المورد؛ تحذير لا قرار.
- **HITL:** لا يصدر AI أمر شراء ولا يعتمد فاتورة ولا يغيّر بيانات بنكية.
- **Evals:** Golden Set لعروض مجهّلة (دقة الاستخراج)، حالات تقسيم وتكرار معلومة (الحساسية والدقة)، حدود القبول من Owner.
- **Autonomy:** Shadow ثم Assist فقط. Kill switch. لا رقم مخترع: كل سعر مصدره عرض أو اتفاقية أو أمر سابق بتاريخ.

## 14) العالمية والامتثال (`PENDING EVIDENCE`)
- قوانين المشتريات والمناقصات الحكومية، ومتطلبات الشفافية: تُحمَّل كحزم بلد بإصدار ومصدر.
- ضريبة القيمة المضافة والخصم من المنبع والفاتورة الإلكترونية: مرجعية لكل دولة، لا نسب مضمّنة بالكود.
- الجمارك والتعريفات وشروط Incoterms وقواعد المنشأ: بيانات مرجعية، ويُتحقق منها رسميًا.
- قوائم العقوبات ومكافحة الفساد (فحص الموردين): المصدر والتحديث `PENDING EVIDENCE`.
- العملات وأسعار الصرف الرسمية وقيود التحويل.
- معايير ISO ذات صلة بسلسلة الإمداد: تُحقق قبل أي ادعاء امتثال.

## 15) الأمان والخصوصية والتدقيق
- **Threat model:** فاتورة وهمية، مورد وهمي، تغيير حساب بنكي بالتحايل، تواطؤ مشتري–مورد، تسريب أسعار عروض، تقسيم أوامر.
- عزل مستأجر وشركات؛ تشفير البيانات البنكية؛ إخفاء العروض قبل الإغلاق.
- Audit: كل تعديل في PO/مورد/تقييم/اعتماد قبل/بعد مع المستخدم والجهاز.
- فصل صلاحية تعديل البيانات البنكية مع تأكيد خارجي (Call-back) كخطوة موثقة.
- احتفاظ حسب سياسة D01؛ منع الحذف.

## 16) الأداء والتوسع
- مؤسسي: عشرات آلاف PO سنويًا، ملايين سطور استلام، مئات المشاريع.
- بحث أصناف وموردين عربي/إنجليزي (تطبيع همزات) سريع.
- المطابقة الثلاثية دفعات خلفية مع إعادة محاولة.
- كاش لمؤشر الالتزام؛ حساب تزايدي.
- أهداف p95 يحددها Owner قبل القياس.

## 17) الترحيل والبدء
- استيراد الموردين وأرصدتهم، وأوامر مفتوحة، واتفاقيات سارية من Excel/ERP مع تنظيف التكرارات (مطابقة بالرقم الضريبي/السجل).
- كتالوج أصناف مبدئي **UNVERIFIED** حتى اعتماده.
- معالج «ابدأ بمصفوفة DOA» بقوالب جاهزة.
- فترة تشغيل مزدوج مع تسوية للـ PO المفتوحة.

## 19) معايير القبول وDoD
- **AC-PRC-01:** Given PR يتجاوز الميزانية المتاحة When يُرفع Then يُحجب أو يتطلب استثناءً معتمدًا موثقًا.
- **AC-PRC-02:** Given PO فوق صلاحية المنشئ When يُرفع Then لا يصدر للمورد إلا بعد اكتمال سلسلة DOA، ولا يعتمد أحد طلبه.
- **AC-PRC-03:** Given أوامر متعددة بنفس المورد والفئة تتجاوز الحد تراكميًا When تُنشأ Then يُكتشف التقسيم ويُطبق الحد الأعلى ويُسجل.
- **AC-PRC-04:** Given فاتورة بفرق عن PO/GRN خارج التسامح When تُدخل Then تُحجز ولا تُدفع حتى الحل الموثق.
- **AC-PRC-05:** Given اعتماد PO أو إلغاؤه When يتم Then يتحدث الالتزام في الميزانية فورًا.
- **AC-PRC-06:** Given مثال PO للشركة When يُعلَّم ويُعتمد قالبه Then تُولَّد الأوامر بنفس الشكل مع إظهار أي فرق قبل الإصدار.
- **AC-PRC-07:** Given مخرجات AI When تُستخدم Then لا قرار شراء أو اعتماد بلا إنسان، ولا سعر بلا مصدر.
- **DoD:** كود + migrations + اختبارات §18 PASS + Golden Sets ضمن الحدود + Evidence Pack + Registers.

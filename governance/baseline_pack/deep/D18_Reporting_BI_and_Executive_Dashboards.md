# D18 — Reporting, BI & Executive Dashboards (التقارير وذكاء الأعمال ولوحات الإدارة)
**Template:** MISHEL_MODULE_DEEP_DIVE_TEMPLATE v1.0 | **Version:** v1.0.0 | **Depth:** D5 (هدف) | **الحالة:** `SPEC DRAFT — لم يُقارَن بالكود بعد` (كل حالة UNKNOWN حتى R0/Forensic)
**ملاحظات:** هذا الموديول «طبقة الرؤية» فوق كل الموديولات: لا يملك بيانات أعمال أصلية، بل يقرأ نسخًا مشتقة من مصادر الحقيقة (D03/D05/D06/D07/D08/D09/D10/D13/D14…) ويعرضها بتعريفات موحدة. أي رقم في لوحة أو تقرير يجب أن يُرد إلى سجل مصدر (Drill-down) ويتطابق مع الدفتر (D13) حيث ينطبق. كل عتبة (أخضر/أصفر/أحمر) وكل KPI target في هذا الملف **مثال توضيحي قابل للضبط من Owner** وليس مرجعًا؛ ومعايير القياس (EVM, TRIR, معايير إفصاح) مراجع بإصدار ومصدر `PENDING EVIDENCE`.

## 1) الهوية

## 2) الغرض والمستخدمون
**المشكلة:** الإدارة تحصل على أرقام من عشرة ملفات Excel يجمعها محاسب آخر كل شهر؛ «الربحية» لها ثلاثة تعريفات حسب من يسأل؛ التقرير لا يُطابق الدفتر؛ لا أحد يعرف من أين جاء الرقم؛ والـ Dashboard المبنية على قاعدة المعاملات تُبطئ التشغيل. المطلوب طبقة معنى (Semantic Layer) واحدة تُعرِّف كل مقياس مرة، وتغذي اللوحات والتقارير والـ AI من نفس التعريف.
| Persona | أهم المهام |
|---|---|
| CEO / مجلس إدارة | صحة المحفظة، الربحية، السيولة، أعلى المخاطر |
| CFO / مدير مالي | التدفق النقدي، الربحية بالمشروع/الشركة، مطابقة الدفتر |
| مدير المشروع | تكلفة/زمن/جودة/سلامة مشروعه، القرارات التصحيحية |
| مدير الموقع / مهندس | مؤشرات يومية: تقدم، عمالة، معدات، ملاحظات |
| مدير مشتريات / عقود / HSE / QA | لوحات قسمه |
| محلل بيانات (Power User) | بناء تقارير وقياسات جديدة |
| مدير النظام | حوكمة التعريفات والتوزيع |
**مقياس النجاح (Owner):** نسبة الأرقام المطابقة للدفتر (هدف 100% لما يمس المال) · زمن إغلاق «تقرير الشهر» · عدد تعريفات المقياس الواحد (هدف: واحد) · نسبة اللوحات المستخدمة أسبوعيًا · زمن الوصول لمصدر الرقم (Drill) · نسبة التقارير الإدارية المولدة تلقائيًا.

## 3) السيناريوهات (Given/When/Then)
**S1 — لوحة CEO للمحفظة:** Given 40 مشروعًا · When يفتح CEO اللوحة · Then يرى لكل مشروع: الإيراد المتوقع، الهامش المتوقع مقابل الميزانية، الإنجاز مقابل المخطط، السيولة، مؤشرات المخاطر (RAG)، مع ترتيب المشاريع بالانحراف، وأي رقم يُنقر ينزل إلى مشروع ← تقرير ← مستند مصدر.
**S2 — مقياس بتعريف واحد:** Given مقياس «التكلفة عند الإنجاز المتوقعة EAC» · When يستخدمه تقرير مالي ولوحة مدير مشروع · Then كلاهما يقرأ نفس تعريف المقياس والنسخة، وتغيير التعريف نسخة جديدة بموافقة لا تغيّر تقارير صدرت.
**S3 — مطابقة الدفتر:** Given لوحة «التكلفة الفعلية» · When يشغّل المحاسب Reconciliation · Then يظهر فرق = 0 أو قائمة فروق بسببها (قيود بعد القفل، توقيت، عملة) ولا تُنشر اللوحة «معتمدة» مع فرق غير مفسَّر.
**S4 — منشئ التقارير (Report Builder):** مستخدم قوي يختار مقاييس وأبعاد معتمدة فقط من Semantic Layer ← فلاتر ← عرض جدول/رسم ← حفظ كتقرير ← مشاركة بصلاحيات.
**S5 — توزيع مجدول:** تقرير أسبوعي للمشروع PDF/Excel/رابط حي يُرسل كل أحد 7:00 لقائمة مستلمين ← كل مستلم يرى ما يحق له فقط (RLS) حتى لو اختلف المحتوى لنفس التقرير.
**S6 — Example-to-Template لتقرير إدارة:** Given تقرير شهري سابق للشركة (Word/PPT/Excel) · When يرفعه المستخدم ويربط كل جدول/رسم/رقم بمقياس من الـ Semantic Layer · Then يُنشأ قالب تقرير بنسخة، وتوليد «تقرير الشهر القادم» يملأ الأرقام من البيانات ويكتب الشرح النصي بمساعدة AI من أرقام ثابتة، مع اختبار تطابق مع الأصل.
**S7 — سؤال بلغة طبيعية:** «كم متأخرات مستخلصات مشاريع القاهرة؟» ← النظام يترجم السؤال إلى استعلام على مقاييس معتمدة فقط ← يعرض الرقم مع التعريف والمصدر ← إن لم يوجد مقياس معتمد يقول «لا أعرف» ويقترح طلب مقياس جديد.
**S8 — تنبيه عتبة:** مؤشر انحراف التكلفة يتجاوز العتبة ← تنبيه لمدير المشروع وCFO ← تصعيد بعد SLA ← ربط بإجراء (D17 خطر / D04 إخطار).
**S9 — تصدير:** تصدير لوحة إلى PDF/Excel بوسم مائي (اسم المستخدم، التاريخ، تصنيف السرية) وتسجيل.
**الحالات الحدية:** مشروع متعدد العملات · بيانات متأخرة من الموقع (Offline) · مقياس يتغير تعريفه وسط السنة (مقارنات تاريخية) · مستخدم يرى مشروعًا واحدًا ويطلب مجموع الشركة · فترة مقفلة وتعديل متأخر · حذف سجل مصدر بعد ظهوره في تقرير.

## 5) دورة الحياة والـ Workflow
- **MetricDefinition:** `Draft → Validated(مقابل مرجع) → Approved → Deprecated`.
- **Dashboard/Report:** `Draft → Reviewed → Published → Archived`؛ لوحة تحتوي مقياس Deprecated تُعلَّم.
- **ReportTemplate:** `Draft → Validated against Example → Approved → Retired`.
- **تقرير دوري رسمي (Management Pack):** `Generated → Reconciled → Reviewed → Approved → Distributed → Locked` (بعد القفل لا تعديل، التصحيح نسخة).
- **Alert:** `Open → Acknowledged → Actioned → Closed/Escalated`.
- **اعتمادات (قابلة للإعداد):** تعريف مقياس مالي (BI Lead + CFO)، نشر لوحة تنفيذية، تغيير عتبة، توزيع خارجي (خارج الشركة).
- **التراجع:** إعادة نسخة سابقة من تعريف/لوحة بنسخة جديدة؛ لا تعديل بأثر رجعي على التقارير المقفلة.

## 6) الصلاحيات
- **Row-Level Security** إلزامي: المستخدم يرى فقط شركاته ومشاريعه وفق D01؛ نفس اللوحة تعرض أرقامًا مختلفة لمستخدمين مختلفين.
- **Column/Field-level:** التكلفة والهامش والرواتب سرية؛ مدير الموقع لا يرى الهامش (حسب إعداد).
- **فصل مهام:** من يعرّف مقياسًا ماليًا لا يعتمده؛ من ينشئ تقريرًا ماليًا رسميًا لا يوزعه خارجيًا بلا اعتماد؛ منشئ التنبيه لا يغير عتبة مالية بلا موافقة.
- Report Builder يعرض المقاييس والأبعاد المعتمدة فقط ولا يسمح SQL حرًا للمستخدم العادي؛ SQL حر (إن وُجد) للمحللين في sandbox مقروء فقط بنفس RLS.
- توزيع خارجي (للعميل/الشركاء) عبر نطاق معزول (D19 Partner Portal / D04).
- **AI يستعلم بصلاحية المستخدم فقط** ولا يتجاوز RLS.

## 7) الأحداث والربط التلقائي
**منتج:** `metric.approved/deprecated` · `dashboard.published` · `report.generated/approved/distributed` · `alert.raised/escalated` · `reconciliation.completed/failed` · `export.performed` · `template.approved`.
**مستهلك (للتغذية):** `invoice.posted/journal.posted` (D13) · `ipc.certified` (D07) · `progress.updated` (D05/D08) · `po.approved` (D06) · `incident.reported` (D10) · `ncr.raised` (D09) · `boq.frozen` (D03) · `vo.approved` (D04) · `period.locked` (D13) · `risk.updated` (D17) · `consolidation.completed` (D19).
**أثر:** `period.locked` ← تجميد Snapshot الفترة وتشغيل Reconciliation تلقائيًا · `reconciliation.failed` ← منع وسم «معتمد» + تنبيه للمالي · `alert.raised` ← إشعار + إنشاء مهمة/خطر (D17) · `metric.deprecated` ← تنبيه أصحاب اللوحات المتأثرة · تأخر مصدر بيانات يُظهر «آخر تحديث» على كل widget.

## 9) الواجهة (UX)
- لوحات حسب الدور (Role-based Home): CEO، CFO، PM، Site، Procurement، HSE… بدون إعداد من المستخدم لتبدأ.
- **بطاقات KPI** بقيمة + اتجاه + مقارنة بالخطة + حالة RAG + «آخر تحديث» + نقرة للـ Drill.
- **Drill-down** على 3 مستويات على الأقل: محفظة ← مشروع ← WBS/CBS/مورد ← مستند المصدر (مع صلاحية).
- لوحات: **التكلفة** (ميزانية/ملتزم/فعلي/متوقع EAC/انحراف) · **الزمن** (SPI، مسار حرج، تأخيرات، Look-ahead) · **النقد** (تدفق متوقع/فعلي، متأخرات، ضمانات) · **المخاطر** (سجل، أعلى 10، تعرض) · **الجودة** (NCR مفتوحة، إعادة عمل) · **السلامة** (حوادث، شبه حوادث، تفتيشات) · **الشراء** (PO متأخرة، التزامات) · **الموارد** (عمالة، معدات).
- شاشة «تعريف المقياس» تعرض الصيغة والمصدر والنسخة والمالك وأمثلة حساب.
- محرر قالب التقرير: ربط عنصر من الملف المرفوع بمقياس بالسحب، ومعاينة جنب الأصل.
- فلاتر مشتركة (فترة، شركة، مشروع، عملة عرض) تُحفظ، عرض بعملة الشركة أو المشروع أو مجموعة مع إظهار سعر التحويل.
- RTL/LTR، موبايل لـ CEO/PM (بطاقات)، وضع Offline للقراءة لآخر Snapshot، طباعة مضبوطة.

## 10) القواعد والحسابات
- **القاعدة الذهبية:** كل رقم = مقياس معتمد × بيانات مصدر؛ لا يحسب الـ widget ولا الـ AI رقمًا من عندهما.
- **مثال تعريفات (صيغ توضيحية تُعتمد من Owner/CFO وتُراجع مع المعيار `PENDING EVIDENCE`):** انحراف التكلفة = EV − AC · CPI = EV ÷ AC · SPI = EV ÷ PV · EAC بطرق قابلة للاختيار (CPI-based / سيناريو مدير المشروع) · هامش المشروع المتوقع = (إيراد متوقع − EAC) ÷ إيراد متوقع · السيولة = نقد وارد − صادر بتواريخ الاستحقاق.
- **تجميع غير تراكمي:** مقاييس نسب (CPI) تُحسب من المجاميع لا بمتوسط النسب.
- **Snapshots:** نهاية كل فترة وقت القفل + يومية للتشغيلي؛ المقارنة التاريخية على نفس نسخة التعريف أو تُعلَّم.
- **العملة:** عرض بعملة اختيار المستخدم بسعر صرف معتمد وتاريخه؛ فرق التحويل ظاهر.
- **الحداثة:** لكل مصدر SLA حداثة؛ تجاوزه يُظهر تحذيرًا على الـ widget.
- **عتبات RAG:** أمثلة قابلة للضبط بالمشروع/الشركة، تُحفظ بنسخة (لا أرقام صلبة في الكود).
- **المطابقة:** مقاييس المال تُسوَّى مع D13 بتسامح يحدده Owner (الافتراضي صفر).
- **تصنيف الجودة:** كل مقياس يُصنَّف `Ledger-reconciled / Operational / Estimated` ويظهر على الواجهة.

## 11) المخرجات والتقارير (Output Factory) — «علّم مرة ثم ولّد»
**محرك Output Factory مشترك** مع D03 (BOQTemplate) وD05 (قوالب الجدول والتقارير) ومع D04؛ يضيف D18 لهم **طبقة ربط المقاييس** (Binding) بحيث تأتي كل أرقام التقرير من الـ Semantic Layer.
| المخرج | يعتمد على |
|---|---|
| التقرير الإداري الشهري للشركة (Management Pack) | قالب + مقاييس معتمدة |
| تقرير المشروع الشهري لمدير المشروع/العميل | قالب مشروع |
| تقرير المحفظة لمجلس الإدارة | مقاييس المحفظة |
| تقرير التدفق النقدي والتنبؤ | D13/D05 |
| تقرير الانحراف (Variance Commentary) | مقاييس + شرح AI من الأرقام |
| لوحة KPI PDF/صورة للطباعة والاجتماعات | Dashboard |
| تقارير تنظيمية/عقدية بتنسيق العميل | قالب العميل |
| Pack المطابقة (Reconciliation Pack) | ReconciliationRun |
**آلية Example-to-Template:** 1) رفع مثال تقرير وتحديد نوعه. 2) استنتاج البنية (أقسام، جداول، رسوم، ترقيم، هوية بصرية، لغة). 3) المستخدم يربط كل رقم/جدول بمقياس وبُعد وفلتر (يقترح النظام الربط بدرجة ثقة). 4) قالب نسخة 1 مع **اختبار تطابق**: إعادة توليد التقرير القديم من بياناته القديمة ومقارنة الأرقام والبنية بالأصل وتسجيل الفروق. 5) اعتماد مسؤول. 6) كل توليد لاحق يمر بفحوص قبل الإصدار: مقاييس Deprecated، بيانات قديمة، فرق مطابقة، خلايا فارغة، تناقض بين قسمين. الأخطاء تظهر ولا تُخفى. أول توليد من كل قالب بمراجعة بشرية. **القالب لا يتغير بصمت** (نسخة جديدة بموافقة، ولا يمس ما صدر).
**التوزيع:** مجدول أو عند حدث، بقنوات (بريد، رابط حي، بوابة، Teams/Slack عبر D20) مع سجل تسليم وإعادة محاولة.

## 12) التكاملات
- **مصادر داخلية:** Outbox/CDC من الموديولات إلى Warehouse؛ لا قراءة مباشرة لجداول domain آخر (M03).
- **أدوات BI خارجية (Power BI/Tableau/Superset…):** اتصال قراءة مقيد على Semantic Layer/Views بنفس RLS (لا على جداول المعاملات)؛ اختيار الأداة `PENDING EVIDENCE` وقرار Owner.
- **Excel:** تصدير بصيغ حية اختياريًا واتصال بيانات محدّث (ODBC/API) بتوكن مقيد.
- **PDF/PPT/Word:** مخرجات رسمية بقوالب الشركة.
- **القنوات:** بريد، Teams/Slack، Webhooks عبر Integration Hub (D20).
- **مصادر خارجية:** أسعار صرف ومؤشرات رسمية (بمصدر وتاريخ)، ملفات Primavera/ERP قائم عند الترحيل.
- لكل تكامل: Mapping وإعادة محاولة وتسوية وCircuit breaker.

## 13) الذكاء الاصطناعي
- **NLQ (Natural-Language Query):** يترجم السؤال إلى استدعاء مقاييس **معتمدة فقط** عبر Semantic Layer (لا SQL حر على الجداول)، يعرض الرقم مع التعريف والفترة والمصدر؛ «لا أعرف» عند غياب مقياس.
- **Narrative Writer:** يكتب شرح الانحرافات والملخص التنفيذي من أرقام ثابتة مُمرَّرة إليه؛ **لا يغيّر ولا يستنتج رقمًا**؛ أي رقم في النص يُتحقق آليًا أنه موجود في بيانات المدخلات (Number Guard).
- **Anomaly & Insight Detector:** يكتشف قفزات غير مبررة، تغيرات اتجاه، مقاييس متناقضة بين لوحتين، وبيانات متأخرة؛ يقترح ولا يتصرف.
- **Binding Assistant:** يقترح ربط عناصر مثال التقرير بالمقاييس (§11) بدرجة ثقة، والقبول بشري.
- **Dashboard Recommender:** يقترح لوحة لدور جديد من أنماط الاستخدام.
- **Evals:** Golden Set من أسئلة حقيقية (مُجهَّلة) بإجابات مرجعية: دقة اختيار المقياس، صحة الفلاتر، صحة الرقم، معدل الرفض الصحيح (لا أعرف)، سلامة RLS (لا يتسرب)، صحة الاستشهاد، دقة Number Guard. حدود القبول من Owner.
- **Autonomy:** Shadow ثم Assist فقط؛ لا إرسال تقرير رسمي أو خارجي تلقائيًا (HITL إلزامي؛ M05 §4). لا اختلاق مقاييس أو تواريخ أو مصادر.
- كل تفاعل مسجل: السؤال، الاستعلام الناتج، الصلاحيات، الإجابة.

## 14) العالمية والامتثال (`PENDING EVIDENCE`)
- إفصاحات التقارير المالية، تقارير الاستدامة (ESG)، وتقارير تنظيمية لكل ولاية: تُحدَّد المعايير بإصدار وسنة وولاية قبل تضمينها؛ لا ادعاء امتثال.
- معايير الصحة والسلامة (معدلات الحوادث): صيغ الحساب مرجع بإصدار ومصدر.
- تنسيق الأرقام والتواريخ والتقويم الهجري/الميلادي، اتجاه الكتابة، والعملات المتعددة.
- متطلبات إقامة البيانات وتصدير البيانات الشخصية في اللوحات (أسماء/رواتب) تحدد مع D01/M04.
- مدد حفظ التقارير الرسمية والـ Snapshots: سياسة قابلة للضبط.

## 15) الأمان والخصوصية والتدقيق
- RLS يُختبر Runtime (لا يكفي واجهة)؛ Warehouse يرث نفس العزل.
- **تصدير:** وسم مائي (مستخدم، وقت، تصنيف، معرّف تتبع)، حدود حجم، تسجيل، منع تصدير جماعي للمواضيع الحساسة بلا صلاحية، وإمكانية سحب روابط مشاركة.
- روابط التوزيع بانتهاء صلاحية وتوكن مقيد.
- منع تسرب الأرقام إلى نماذج خارجية: تمرير الحد الأدنى وفق M05 وتجهيل عند الحاجة.
- Audit: من فتح/صدّر/وزّع/غيّر تعريفًا أو عتبة، قبل/بعد.
- حماية من «الاستنتاج بالتجميع» (Inference): حد أدنى لحجم المجموعة عند عرض رواتب أو بيانات شخصية مجمعة.

## 16) الأداء والتوسع
- عشرات المشاريع × ملايين سجلات fact، مئات المستخدمين المتزامنين على اللوحات.
- Materialized aggregates وSnapshots مسبقة للمقاييس الثقيلة؛ Cache بسياسة إبطال مرتبطة بأحداث المصدر.
- فصل الحمل: استعلامات BI لا تؤثر على OLTP.
- أهداف p95 (فتح لوحة، Drill، توليد تقرير 50 صفحة، استعلام NLQ) يحددها Owner قبل القياس.
- حدود على استعلامات Report Builder (مدة، حجم) وإلغاء آمن.
- تأخر Warehouse عن OLTP (Freshness Lag) مقاس ومعلن.

## 17) الترحيل والبدء
- قائمة مقاييس أساسية جاهزة (مكتبة تعريفات) تُراجع وتُعتمد لكل شركة، **مصنفة UNVERIFIED** حتى الاعتماد.
- استيراد تقارير الإدارة السابقة (Excel/PPT) لتكوين قوالب وتحديد المقاييس المستخدمة فعليًا (Teach by Example).
- بناء Snapshots تاريخية من بيانات مرحَّلة للمقارنة (مع تعليم الجودة).
- مطابقة أول 3 فترات مع دفاتر النظام القديم قبل الاعتماد.
- لوحات افتراضية لكل دور تعمل من اليوم الأول بالبيانات المتاحة.

## 19) معايير القبول وDoD
- **AC-RPT-01:** Given مقياس معتمد When يظهر في أي لوحة أو تقرير أو إجابة AI Then بنفس التعريف والنسخة والقيمة، مع إمكانية الوصول لتعريفه ومصدره.
- **AC-RPT-02:** Given مقياس مالي When يُنشر معتمدًا Then يطابق D13 بالتسامح المحدد، وإلا يُمنع الوسم ويُعرض سبب الفرق.
- **AC-RPT-03:** Given رقم في لوحة When يُنقر Then يصل المستخدم (بحسب صلاحيته) إلى السجلات المصدر خلال عدد النقرات المحدد.
- **AC-RPT-04:** Given مثال تقرير إداري للشركة When يُعلَّم ويُعتمد قالبه Then توليد تقرير الفترة التالية يطابق البنية والتنسيق، وأرقامه من المقاييس، ويظهر أي فرق قبل الإصدار.
- **AC-RPT-05:** Given مستخدم بصلاحيات محدودة When يستعلم بأي وسيلة (لوحة، تصدير، API، NLQ) Then لا يرى أي بيانات خارج نطاقه.
- **AC-RPT-06:** Given سؤال بلغة طبيعية بلا مقياس معتمد When يُطرح Then الرد «لا أعرف» مع اقتراح، لا رقم مختلق.
- **AC-RPT-07:** Given تصدير When يتم Then وسم مائي وتسجيل كاملان.
- **DoD:** كود + migrations + اختبارات §18 PASS + Golden Sets (NLQ، قوالب، Number Guard) ضمن الحدود + Evidence Pack + Registers.

## 21) الفجوات والمخاطر

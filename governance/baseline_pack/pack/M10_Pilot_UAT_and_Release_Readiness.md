# M10 — Pilot, UAT & Release Readiness
**Version:** v1.0.0 | لا يُباع ولا يُسلَّم لعميل إلا بعد Pilot ناجح وقائمة Production Ready (§4) مكتملة بأدلة. كل الأرقام والعتبات يحددها Owner (`PENDING OWNER DECISION`).

## 1) خطة الـ Pilot (قالب لكل عميل تجريبي)
```
PILOT ID: P-__ | العميل (مُجهَّل في السجلات) | تاريخ البدء/الانتهاء
النطاق: الموديولات وGolden Flows المشمولة (M06) | خارج النطاق
بيانات: مصدرها، تجهيلها، ترحيلها (Migration Plan) وفحص سلامتها
المستخدمون: أدوار وأعداد | مدرَّبون؟ (نعم/لا)
بيئة: Staging معزولة | نسخة الكود (commit) | نسخة الإعدادات
مقاييس النجاح (يحددها Owner): زمن إنجاز Flow · عدد الخطوات · أخطاء أرقام · تدخل بشري · رضا المستخدم · أعطال
خط الأساس: القياس بالطريقة الحالية للعميل (Excel/نظام آخر)
قنوات الدعم والتصعيد | خطة الخروج (Exit/Rollback)
```
قواعد: بيانات حقيقية مُجهَّلة فقط في غير الإنتاج · لا ميزة AI في Pilot قبل اجتياز Evals (M05) · كل ملاحظة تُسجَّل Issue في نفس اليوم.

## 2) UAT
- سيناريوهات مكتوبة بلغة العميل مشتقة من Golden Flows، بنتائج متوقعة.
- المنفِّذ مستخدم العميل لا فريق التطوير. التوثيق: لقطات + زمن + ملاحظات.
- تصنيف النتائج: Blocker / Critical / Major / Minor. لا قبول مع Blocker أو Critical مفتوح.
- توقيع قبول UAT من ممثل العميل ومن Owner.

## 3) Go / No-Go
| المحور | سؤال | دليل |
|---|---|---|
| وظيفي | Golden Flows تعمل على بيانات واقعية؟ | E1 |
| مالي | الأرقام تطابق المرجع؟ | تسوية |
| أمان وعزل | اختبارات M04/M07 PASS؟ | Logs |
| أداء | ضمن أهداف Owner؟ | تقرير |
| استعادة | استعادة نسخة احتياطية مجربة؟ | محضر |
| AI | Evals ضمن الحدود؟ | Eval Register |
| تشغيل | مراقبة وتنبيهات ودعم جاهزة؟ | قائمة |
| قانوني/امتثال | العقد وسياسة الخصوصية والامتثال المحلي؟ | مراجعة مختص |
القرار: GO / CONDITIONAL GO (شروط ومواعيد) / NO-GO — يوقّعه Owner في Approval_Register.

## 4) قائمة Production Ready (إلزامية — كلها بدليل)
- [ ] R0 وشهادة التشغيل (M07 §9) PASS.
- [ ] Golden Flows 1–3 على الأقل PASS ببيانات واقعية.
- [ ] Open Blocker/Critical = 0؛ Major لها خطة ومواعيد.
- [ ] عزل المستأجرين (RLS) واختبارات الصلاحيات/SoD/DOA PASS.
- [ ] لا أسرار في الكود؛ إدارة أسرار وتدوير مفاتيح؛ فحص ثغرات للمكتبات.
- [ ] تشفير أثناء النقل وفي التخزين؛ سجل تدقيق غير قابل للتعديل.
- [ ] نسخ احتياطي تلقائي + استعادة مجربة؛ RPO/RTO محققان.
- [ ] مراقبة (Logs/Metrics/Alerts) وتنبيهات بمالك لكل تنبيه.
- [ ] CI/CD بيئات منفصلة، ترقية وتراجع مجربان، Migrations من الصفر.
- [ ] أداء وتحميل وSoak ضمن أهداف Owner.
- [ ] AI Gateway وKill Switch وEvals (إن وُجد AI) PASS.
- [ ] تكاملات الإصدار الأول مجربة مع Retry وDead-letter.
- [ ] وثائق: دليل مستخدم، دليل مدير، دليل تشغيل (Runbook)، دليل ترحيل بيانات.
- [ ] تدريب منفذ وقنوات دعم وSLA معتمد.
- [ ] سياسة خصوصية وشروط استخدام ومراجعة قانونية وامتثال محلي (Compliance Register).
- [ ] خطة ترحيل بيانات العميل واختبار تسوية بعد الترحيل.
- [ ] Release Notes وVersion Policy وسياسة Deprecation.

## 5) قائمة الإصدار (لكل Release)
نسخة مجمدة وCommit/Tag · Changelog · Migrations مراجعة ومجربة على نسخة من بيانات الإنتاج · Smoke Test بعد النشر · نافذة نشر معلنة · خطة تراجع مجربة · موافقة Owner.

## 6) الدعم والحوادث
- مستويات الدعم L1/L2/L3، أوقات الاستجابة (SLA) يحددها Owner.
- تصنيف الحوادث Sev1–Sev4 مع مواعيد تصعيد. Sev1 (توقف أو تسرب بيانات أو خلل مالي): تواصل فوري، عزل، إيقاف الميزة المتأثرة (Kill Switch)، علاج، ثم Post-mortem خلال أيام بلا لوم، ويُسجل في Issue/Risk Registers.
- تسرب بيانات شخصية: إجراءات الإبلاغ حسب القانون المطبق (تُراجع مع مختص قبل الإصدار).

## 7) التراجع (Rollback)
لكل Release: تراجع الكود، تراجع/توافق Migrations (Expand/Contract)، استعادة بيانات عند الحاجة. تُجرَّب في Staging قبل الإنتاج. تغييرات مالية لا تُحذف بل تُعكس بقيود.

## 8) ما بعد الإطلاق
مراجعة أسبوعية للمقاييس والأخطاء في أول 90 يومًا · Eval دوري للـ AI · قياس الاعتماد (Adoption) · تغذية Backlog بملاحظات الميدان عبر Change Control.

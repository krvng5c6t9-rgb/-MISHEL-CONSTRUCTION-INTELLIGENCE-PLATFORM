# M07 — Test & Runtime Certification Protocol
**Version:** v1.0.0 | الحقيقة في البرمجيات = التنفيذ. لا يُسمى شيء VERIFIED إلا بدليل E1 (Log/نتيجة تشغيل) محفوظ.

## 1) مستويات الاختبار
| المستوى | الغرض | مطلوب لـ |
|---|---|---|
| Unit | منطق وقواعد وحسابات | كل دالة أعمال/حساب |
| Integration | Module + DB + API + Events | كل Work Package |
| Contract | تكاملات خارجية وواجهات داخلية | كل تكامل |
| E2E | سلاسل أعمال كاملة | Golden Flows (M06) |
| Negative/Hostile | صلاحيات، عزل، تكرار، تزامن، حقن | كل مسار حرج |
| Performance/Load/Soak | أداء وتحمل | قبل Pilot |
| Recovery | نسخ احتياطي، استعادة، DR، ترقية/تراجع | قبل Release |
| AI Evals | دقة وسلامة الـ AI (M05) | كل ميزة AI |
| UX/UAT | استخدام حقيقي | Pilot |
لكل متطلب (Requirement) Test ID، ولكل Test ID نتيجة وتاريخ ونسخة كود.

## 2) فحص R0 (إجرائي)
1. `node -v / npm -v` وتسجيلها. 2. `npm ci` من lockfile (أو إنشاء lockfile ثم إثبات `npm ci`). 3. Postgres نظيف (نسخة مسجلة) ثم تنفيذ migrations بالترتيب مع checksum وقياس الزمن وتسجيل أول فشل. 4. Build للباك والفرونت وحفظ Hashes. 5. تشغيل الاختبارات الموجودة وتسجيل الناجح والفاشل والمُهمَل. 6. E2E الأساسي حلقة حلقة (Lead/Tender→Project→BOQ→PR→RFQ→PO→GRN→Invoice→Cost→GL→IPC→Payment) مع تسجيل أول كسر. 7. اختبارات سلبية أولية.
**المخرج:** تقرير صفحة + مجلد Logs. لو لم تُنفَّذ خطوة: `UNVERIFIED` وسبب.

## 3) اختبارات إلزامية لكل مسار حرج
### سلامة مالية
توازن القيود (مدين=دائن) · عدم ترحيل مكرر · Period-lock · العكس والتصحيح · تقريب وعملات · مطابقة ثلاثية (PO/GRN/Invoice) · مستخلص (استقطاعات، Retention، دفعات مقدمة) · تسوية.
### العزل والصلاحيات
محاولة قراءة/كتابة/بحث/تقرير/ملف من مستأجر آخر ومن مشروع غير مصرح · تجاوز الدور · الاعتماد الذاتي · تجاوز عتبات DOA · SoD.
### التزامن والتكرار
طلبان متزامنان لنفس السجل · إعادة إرسال نفس الطلب (Idempotency) · سباق اعتماد · فشل منتصف المعاملة.
### الأحداث والتكامل
فقدان حدث · تكرار حدث · ترتيب معكوس · فشل مستهلك · Dead-letter · تسوية مع نظام خارجي.
### ملفات ومستندات
نوع/حجم/ملف خبيث · روابط موقعة · نسخ المراجعات · Transmittals.

## 4) قياس الأداء
أهداف تُحدد لكل موديول قبل القياس: زمن استجابة (p50/p95)، معدل خطأ، سعة مستخدمين متزامنين، حجم بيانات. اختبار تحميل تدريجي ثم Soak. النتائج مع بيئة القياس. القيم المقبولة يحددها Owner.

## 5) الاستعادة والتشغيل
استعادة نسخة احتياطية في بيئة نظيفة والتحقق من سلامتها · محاكاة فشل (إيقاف خدمة، انقطاع قاعدة) · RPO/RTO المحققان مقابل الهدف · ترقية وتراجع بدون فقد إعدادات العميل.

## 6) تعريف Evidence Pack لكل Work Package
Test IDs + نتائج + Logs + نسخة الكود (commit hash) + بيئة التنفيذ + تاريخ + من نفّذ. يُحفظ ويُربط في Evidence_Register وRequirement_Trace.

## 7) سياسة الفشل
- فشل Critical: يوقف الـ Gate. - فشل متقطع (Flaky): لا يُهمل، يُسجل Issue ويُحل سببه. - اختبار معطّل: يُعامل كفشل حتى يُسجل سبب وقرار.
- تغطية الاختبار وحدها ليست جودة؛ المطلوب مسارات حرجة وسيناريوهات سلبية.

## 8) المصفوفات
Test Matrix: Requirement ← Test IDs ← النوع ← الحالة ← آخر تشغيل ← الدليل.
Defect Matrix: Issue ← الشدة ← الموديول ← الحالة ← الإغلاق بدليل.

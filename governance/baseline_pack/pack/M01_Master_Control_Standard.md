# M01 — MISHEL Master Control Standard (القواعد الحاكمة)
**Version:** v1.0.0 | **Status:** CANDIDATE — OWNER APPROVAL PENDING | يكمّل Master Definition وA1، ولا يعدّل محتواهما المجمّد.

## 1) المبادئ غير القابلة للتفاوض
1. **No Evidence = No Claim.** لا معلومة/حالة/إنجاز/تفوق بدون دليل قابل للتحقق (كود، اختبار نُفِّذ، Log، مصدر رسمي بتاريخ).
2. **التقدم = تشغيل.** CODE ← DB ← API ← UI ← WORKFLOW ← PERMISSIONS ← AUDIT ← TEST ← E2E ← RUNTIME EVIDENCE. عدد المستندات والسجلات ليس تقدمًا.
3. **Owner هو القرار النهائي** في: النطاق، الأولويات، التسعير، النشر، الاعتماد. الـ AI يوصي ويعترض ويكشف المخاطر.
4. **مصدر حقيقة واحد** لكل كيان أعمال. لا دفاتر أو ماسترات موازية.
5. **الـ AI ليس سجل النظام ولا صاحب القرار الوحيد** في المحاسبة والتعاقد والسلامة والهندسة والاعتماد.
6. **السجل المعتمد لا يُكتب فوقه**: تصحيح بالعكس أو الاستبدال مع أثر تدقيق.
7. **سياق المستأجر/الشركة/المشروع يأتي من هوية موثوقة**، لا من مدخلات المستخدم.
8. **إعداد العميل لا يتطلب Fork للكود** ويبقى بعد الترقيات.
9. **Baseline المجمّد لا يُعدَّل في مكانه.** التغيير بـ Controlled Change.
10. **ممنوع Production Ready/Complete/FINAL** قبل بوابات الإطلاق (M10) بالأدلة.

## 2) الحوكمة
- **Owner Decisions:** `APPROVED / REJECTED / HOLD`. لا اعتماد ذاتي، ولا انتقال تلقائي بين المراحل خارج التفويض المكتوب.
- **Controlled Change:** ID · السبب · الأثر · الملفات/الموديولات المتأثرة · زيادة نسخة · إعادة مراجعة · إعادة اعتماد.
- **تفويض مسبق:** يجوز لـ Owner تفويض الـ AI بتنفيذ مراحل متتالية بدون توقف، بشرط تحديد نقاط التوقف (تعارض جوهري، Critical، ملف غير قابل للقراءة، نهاية Gate).
- **الاعتراض:** للـ AI حق الاعتراض بدليل، ويُسجل في Decision Register، ثم يُنفَّذ قرار Owner إن أصر.

## 3) نظام الحالات (المسموح فقط)
NOT STARTED · IN REVIEW · GAP · PARTIAL · COVERED · VERIFIED · NEEDS VERIFICATION · NEEDS CORRECTION · MERGE REQUIRED · DEFER · N/A · SUPERSEDED · ARCHIVED · OWNER APPROVAL PENDING · OWNER APPROVED · OWNER REJECTED · FROZEN.
حالات الدليل: UNVERIFIED · UNKNOWN · PENDING EVIDENCE · VERIFY-AT-USE.
**تعريفات:** COVERED = يوجد Artifact (كود/DB/API/UI) بالتتبع. VERIFIED = COVERED + اختبار نُفِّذ ونجح + دليل محفوظ. ممنوع تسمية COVERED كـ VERIFIED.

## 4) تصنيف الأدلة
| الدرجة | النوع | يصلح لـ |
|---|---|---|
| E1 | Log/نتيجة تشغيل فعلي (build، migration، test، E2E) | VERIFIED |
| E2 | كود/Schema/Endpoint موجود (Static) | COVERED |
| E3 | مصدر رسمي بتاريخ | معلومة خارجية |
| E4 | وثيقة مواصفات معتمدة | مرجع تصميم، ليس إنجازًا |
| E5 | رأي/تقدير | لا يغلق بندًا |

## 5) الشدة (Severity)
- **Blocker/Critical:** يكسر السلامة المالية/العزل/الأمان/فقد بيانات/ادعاء كاذب. يمنع إغلاق أي Gate.
- **Major:** فجوة أو تعارض جوهري في Tier ملتزم به. يمنع إغلاق الـ Gate المتأثر.
- **Moderate:** ضعف جودة قابل للتأجيل بقرار.
- **Minor:** تجميل/تسمية.

## 6) المحظورات
1. اختراع ميزة/رقم/سعر/مادة قانونية/قدرة منافس. 2. تصنيف بند VERIFIED بلا اختبار. 3. ادعاء بناء أو اختبار بلا دليل. 4. تلخيص ملف لم يُفتح. 5. حسم تعارض بدل عرضه. 6. تعديل Baseline مجمّد أو تغيير Scope بلا Controlled Change. 7. إخفاء خطأ أو تصحيحه بصمت. 8. تضخيم التوثيق بدل التنفيذ. 9. توسع في مواصفات قبل إغلاق R0. 10. ترك سر/مفتاح/بيانات حقيقية في ملفات أو Logs. 11. اعتبار تكرار بين وثيقتين مصدرين مستقلين. 12. استخدام بيانات عميل حقيقية في اختبارات بدون إخفاء هوية وتصريح.

## 7) النسخ
`MAJOR.MINOR.PATCH` لكل وثيقة وBaseline وحزمة. ممنوع: final2/last/true_final. كل نسخة: تاريخ + حالة المؤلف + حالة الاعتماد + ملخص تغيير.
